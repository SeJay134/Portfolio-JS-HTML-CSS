UUID

1. Фронтенд

При первом открытии сайта генерируешь UUID и сохраняешь его в localStorage.

let sessionId = localStorage.getItem("chat_session");

if (!sessionId) {
    sessionId = crypto.randomUUID();
    localStorage.setItem("chat_session", sessionId);
}

Теперь у каждого посетителя будет свой идентификатор.

При каждом запросе отправляешь его на сервер.

const response = await fetch("/chat", {
    method: "POST",
    headers: {
        "Content-Type": "application/json"
    },
    body: JSON.stringify({
        session_id: sessionId,
        message: chatInput.value
    })
});

5. Ограничение памяти

Иначе один пользователь сможет накопить тысячи сообщений.

Я бы сразу добавил

MAX_HISTORY = 20

После каждого ответа

if len(history) > MAX_HISTORY:
    history[:] = history[-MAX_HISTORY:]

или, если считать парами пользователь/ассистент, хранить последние 10 обменов.

6. Очистка старых сессий

Хранить их вечно тоже не стоит.

Можно хранить так

chat_sessions = {
    session_id: {
        "history": [...],
        "last_seen": time.time()
    }
}

И раз в несколько минут удалять

if now - last_seen > 3600:
    del chat_sessions[session_id]

Например, через час бездействия.

7. Что это даст

Пользователь A

UUID_A

Hi
Tell me about Sergei
What projects?

Пользователь B

UUID_B

Hello
Who are you?

Истории никогда не пересекутся.

Единственное улучшение, которое я бы предложил

Не доверять UUID полностью. Любой может вручную подставить чужой UUID. Для портфолио это не критично, но если захочешь сделать чуть надежнее, можно хранить UUID в защищенной cookie или подписывать его на сервере. Для демонстрационного проекта текущего уровня localStorage + UUID — вполне разумное и простое решение.
